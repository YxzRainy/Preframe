# 片策

「片策」是一套本地运行的短视频内容生产工作台。输入选题、平台、内容主体、内容领域与内容风格后，它生成三份一致的核心工作稿：`01_创作简报.md`、`02_拍摄执行稿.md`、`03_发布与复盘.md`。

项目同时提供本地 CLI 和 Next.js 可视化工作台。应用只监听 `127.0.0.1`，本地模式不提供账号系统、云端项目库、自动上传或发布中心。CLI 使用项目根目录 `.env`；本地 Web 工作台的用户 Key 使用当前浏览器的安全 Cookie；项目、配置、素材索引、备份和生成文件在本地模式均写入本机文件系统。

## 环境要求

- Node.js 18 或更高版本
- npm
- 可用的 DeepSeek API Key

## 安装

```bash
git clone <你的仓库地址>
cd /path/to/项目目录
npm install
```

## Web 可视化工作台

开发模式启动：

```bash
npm run dev
```

浏览器打开 [http://localhost:3000](http://localhost:3000)。首页可以填写选题并生成三份核心工作稿；“历史项目”页面读取本地 `output` 目录；项目详情页支持 Markdown 编辑、版本归档、导出、素材扫描和镜头执行。镜头任务直接从 `02_拍摄执行稿.md` 的镜头执行表解析。拍摄复盘会生成一份同步后的下一版拍摄执行稿，并保留可匹配镜头的现场状态、素材判断与备注。`03_发布与复盘.md` 可自动提炼为可复制的封面视觉提示词；历史视觉提示词文档继续兼容。

生产模式本地运行：

```bash
npm run build:web
npm run web
```

本地 Web API Route 默认可从本机 `.env` 读取 DeepSeek 配置；在“设置 → 模型”中输入自己的 Key 后，Web 端会将它写入当前浏览器的 HttpOnly Cookie，不会写入全站环境变量，也不会保存到 `localStorage`。每次模型请求只读取当前浏览器对应的 Key。Web 端固定使用 `deepseek-v4-flash`；本地模式下素材扫描和项目文件操作都针对运行片策的这台电脑。

## 配置 DeepSeek API

复制环境变量示例：

```bash
cp .env.example .env
```

编辑 `.env`：

```env
DEEPSEEK_API_KEY=你的DeepSeek_API_Key
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-v4-flash
```

- `DEEPSEEK_API_KEY` 必填，工具不会在代码或输出文件中保存它。
- `DEEPSEEK_BASE_URL` 可选，默认值为 `https://api.deepseek.com/v1`。
- 当前 Web 端固定使用 `deepseek-v4-flash`；`DEEPSEEK_MODEL` 仅保留给本地 CLI 使用。
- `.env` 已加入 `.gitignore`，不要将真实密钥提交到 Git。

## 本地数据边界

- `npm run dev` 和 `npm run web` 默认只监听 `127.0.0.1`，局域网和公网设备无法访问。
- 项目文档保存在本机 `output/` 或你选择的本地工作区。
- 应用设置、灵感、素材索引和备份保存在本机 `.piance/`。
- CLI 的 DeepSeek API Key 保存在本机 `.env`；Web 端用户自定义 Key 保存在当前浏览器的 HttpOnly Cookie，不写入项目输出或配置备份。
- 当前项目仍是本地文件工作台：项目文件不会上传到片策自建云端，也没有账号级跨设备同步。
- 使用 DeepSeek 时，为完成生成所提交的文字提示和必要内容会发送给对应 API 供应商；如果需要完全离线，必须改用本地模型。
- 最终发布由用户在目标平台人工完成，再把真实链接和数据写回 `03_发布与复盘.md`。

如果 API Key 缺失、网络失败、API 报错、模型返回为空或输出无法解析，CLI 会显示对应错误，不会写入不完整的项目。

## 使用方法

### 创建内容项目

```bash
npm run generate
```

按照提示输入选题主题、平台、内容主体、内容领域、内容风格、目标用户及可选补充要求。内容主体和领域均支持自由填写。三份核心工作稿保存在 `output/<选题>/`。若项目目录重名，会自动追加 `_2`、`_3`，不会覆盖旧项目。

### 修改已有内容

```bash
npm run refine
```

选择已有项目、要修改的口播脚本/分镜与剪辑节奏/封面标题与发布文案（或全部），再输入修改意见。修改结果以 `_修改版.md` 保存，原文件不会被覆盖。旧项目中的口播脚本、分镜草案和封面标题文件名会自动兼容。

### 扫描素材文件夹

```bash
npm run scan
```

输入本地素材目录，工具会递归整理普通文件的名称、类型、大小、修改时间、子文件夹和可能用途。选择项目后，会写入 `00_素材索引.md`。第一版只读取文件元数据，不识别视频画面或图片内容；符号链接会被跳过。

### 其他命令

```bash
npm run dev:cli -- --help  # 查看 CLI 帮助
npm run build          # 编译 TypeScript 到 dist/
npm start -- generate  # 使用编译产物运行 generate
```

## 示例输出

```text
output/
  AI为什么替代不了人类/
    00_素材索引.md                 # 可选
    01_创作简报.md
    02_拍摄执行稿.md
    02_拍摄执行稿_修改版.md        # 可选
    03_发布与复盘.md
    project.json
```

`project.json` 记录输入参数、模型、统一 projectBrief、自动质量门结果、生成耗时、镜头任务和项目阶段，不包含 API Key。

## 旧项目迁移

已经生成过旧版 8/10 份文档的项目，打开项目后会标记为“历史项目”，并提供“迁移到新版工作流”按钮。迁移会先把旧文档写入项目版本归档，再基于旧项目内容生成 `01_创作简报.md`、`02_拍摄执行稿.md`、`03_发布与复盘.md`，通过新版质量门后才切换项目版本。迁移失败时旧文档不会删除。

## 项目结构

```text
src/
  commands/       # generate、refine、scan 交互命令
  prompts/        # 模型提示词与结构化输出解析
  services/       # 模型、文件、项目和素材扫描服务
  utils/          # 文档定义、文件名清理与 Markdown 格式化
  index.ts        # CLI 入口
web/
  app/            # Next.js 页面与 API Route
  components/     # 表单、项目列表与 Markdown 预览
```

命令层、模型调用和文件服务彼此分离，后续 Next.js 页面可直接复用 `prompts/` 与 `services/` 中的核心逻辑。

## 复盘与内容质量

- 拍摄复盘记录计划/实际、现场问题、补拍和新增镜头。
- 复盘修订只更新唯一真源 `02_拍摄执行稿.md`，不再维护四份重复文档。
- 内容质检属于内部自动质量门：系统能修的问题先修复，不生成一份报告让用户返工。
- `03_发布与复盘.md` 预留 24 小时、72 小时和 7 天真实数据回收。
